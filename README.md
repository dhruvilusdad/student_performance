# AI Student Performance Analytics

An interactive Streamlit-based AI Student Performance Analytics system that analyzes student data, compares machine learning models, predicts student performance, and provides data-driven insights through an interactive dashboard.

This machine-learning-powered application analyzes student academic and demographic data, compares multiple models, predicts final performance, and presents results through a dashboard. It adapts preprocessing and prediction inputs to the real dataset schema and does not create synthetic data.

## Problem Statement

Student datasets often combine numerical and categorical attributes, inconsistent missingness, and different outcome scales. This project provides a repeatable workflow to inspect the supplied data, fit preprocessing only on training folds, evaluate candidate regressors fairly, and present results in an interactive dashboard.

## Objectives and Features

- Inspect dimensions, schema, data types, missing cells, and duplicates.
- Detect numerical and categorical predictors from the CSV itself.
- Identify a recognized numeric performance target only when the match is unique; otherwise require a user decision.
- Impute missing data, scale numerical features, and one-hot encode categorical features in a Scikit-learn pipeline.
- Compare Linear Regression, Decision Tree, Random Forest, and Gradient Boosting, plus XGBoost when installed.
- Tune Random Forest and Gradient Boosting with bounded randomized searches.
- Report holdout MAE, MSE, RMSE, and R², plus training-fold cross-validation results.
- Save the fitted preprocessing and estimator together with prediction metadata.
- Show model-level feature importance and attempt SHAP explanations when the optional package works with the selected estimator.
- Explore the data and make predictions through a Streamlit dashboard.

## Tech Stack

Python, Pandas, NumPy, Scikit-learn, Matplotlib, Seaborn, Plotly, Joblib, and Streamlit. XGBoost and SHAP are optional; the main workflow remains usable without them.

## Dataset

Obtain the student performance CSV from the Kaggle source you selected and place it at:

```text
data/student-performance.csv
```

The dataset is not included in this public repository. Student academic/demographic data should only be redistributed when its source license and permissions allow it; `.gitignore` excludes CSVs under `data/`. The loader reports a clear message if the file is missing, empty, or unreadable. No synthetic or dummy records are generated.

The supplied CSV was inspected as 649 rows and 33 columns. `G3` is the performance target and has observed integer values from 0 to 19. The sidebar target selector is fixed to `G3`; `G1`, `G2`, and the other non-target columns remain prediction features. The input controls are generated from the actual CSV columns rather than hard-coded feature names.

## Data Preprocessing

The target must be numeric or numeric-compatible. Rows without a usable target and exact duplicate records are excluded from training. Entirely missing feature columns are excluded. Columns with at least 90% numeric-compatible observed values are coerced to numerical predictors; other columns are treated as categorical. Numerical features receive median imputation and standard scaling; categorical features receive most-frequent imputation and `OneHotEncoder(handle_unknown="ignore")`. Missing and infinite numerical values are imputed. All preprocessing is contained in the estimator pipeline and fitted only within the training split/CV folds, preventing preprocessing leakage.

## Exploratory Data Analysis

Open `notebooks/EDA.ipynb` after adding the CSV. It contains data overview, missingness and duplicate checks, descriptive statistics, target discovery, numeric and categorical distributions, a correlation heatmap, feature-versus-target views, and outlier summaries. It uses Matplotlib, Seaborn, and Plotly without relying on a fixed schema.

## Machine Learning and Evaluation

The training workflow uses a reproducible 80/20 holdout split. Baselines include Linear Regression, Decision Tree, Random Forest, and Gradient Boosting. XGBoost is included when importable. RandomizedSearchCV performs small bounded searches for Random Forest and Gradient Boosting. Model selection uses the lowest cross-validation RMSE on the training partition. The untouched holdout is reserved for final MAE, MSE, RMSE, and R² reporting. The selected pipeline is refitted on all usable rows only after evaluation, then saved as `models/best_model.pkl`; reported metrics remain from the holdout.

The full comparison is saved to `models/model_comparison.csv`, and target, feature, model, metric, and category-scale metadata is saved to `models/metadata.json` and embedded in the Joblib artifact.

## Explainable AI

Tree models expose their built-in feature importance. One-hot encoded importances are grouped back to their original columns. SHAP is optional and attempted only when requested in the dashboard; any missing or incompatible SHAP installation falls back to built-in importance. These explanations describe model-level predictive association and should not be interpreted as causal claims.

## Streamlit Application

The dashboard includes Dashboard, Student Prediction, Data Analytics, Model Performance, Feature Importance, and About Project views. Input controls are generated from the loaded feature columns. `G3` is the fixed target; train a model before requesting a prediction. Since this dataset's observed target range is 0–19, performance categories use four equal-width bands across that observed range rather than 0–100 thresholds. The logic and observed limits are stored in the artifact metadata.

## How to Run

1. Place the Kaggle CSV at `data/student-performance.csv`.
2. From this project directory, run the application entry point:

```bash
streamlit run app.py
```

3. In the sidebar, confirm the fixed `G3` target for this dataset.
4. Select **Train / Retrain Models**. The app evaluates candidates and saves the best pipeline and reports under `models/`.
5. Use Student Prediction and the analytics/model pages.

The first file to run is `app.py`. The notebook is an optional EDA-first workflow; running it does not train or save the production model.

## Example Usage

Once training has completed, enter values in the generated feature controls and select **Predict Performance**. The app returns a numeric prediction, its scale-aware performance category, the selected model name, and the model's most influential overall features.

## Results

Training was run on the supplied 649-row CSV using `G3` as the target and a fixed 80/20 holdout split. Tuned Random Forest was selected by training-split cross-validation RMSE. Holdout results:

| Model | MAE | MSE | RMSE | R² | CV RMSE | CV R² |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Random Forest (tuned) | 0.711 | 1.447 | 1.203 | 0.852 | 1.206 | 0.857 |
| Gradient Boosting (tuned) | 0.730 | 1.550 | 1.245 | 0.841 | 1.216 | 0.856 |
| Random Forest | 0.754 | 1.567 | 1.252 | 0.839 | 1.216 | 0.855 |
| Gradient Boosting | 0.778 | 1.768 | 1.330 | 0.819 | 1.261 | 0.843 |
| Linear Regression | 0.766 | 1.478 | 1.216 | 0.848 | 1.305 | 0.836 |
| Decision Tree | 0.838 | 2.746 | 1.657 | 0.718 | 1.707 | 0.722 |

The saved pipeline is refitted on all 649 usable rows after evaluation; the displayed metrics are from the untouched 130-row holdout. The observed `G3` range is 0–19, so performance categories use four equal-width bands over that observed range, not the 0–100 thresholds. `G1` and `G2` are included predictors and are important signals; this model therefore predicts final grade when earlier-period grades are available, not a pre-term estimate. Results can vary with a different dataset or split.
